# 开发与维护工具

这个目录包含依赖准备、原创资源生成、地图施工和原生检查工具。文件名的 R 编号表示最初引入阶段，**不是是否仍被使用的判断依据**；不少当前工具继续导入早期的共享模块。

## 从这里开始

| 入口 | 用途 |
|---|---|
| `python tools/bootstrap_dev_dependencies_r24.py` | 下载并校验源码构建所需的固定公共依赖 |
| `python tools/bootstrap_dev_dependencies_r24.py --check` | 只核对依赖，不下载 |
| `gradlew build` | 运行构建与已注册的 Java 回归任务；见 [测试说明](../src/test/README.md) |
| [素材登记](../docs/ASSETS.md) | 找到具体资源的生成器、来源和许可 |
| [地图编辑协议](../docs/MAP_EDITING_PROTOCOL.md) | 地图工具使用前的测量、备份、差量和交付要求 |

## 工具如何分类

- `gen_*`、`build_*`、`make_*`：资源或交付制作；有些需要本机原始素材。
- `query_*`、`survey_*`、`audit_*`、`verify_*`：查询、测量与检查；使用前仍须读脚本，名字不能保证无写操作。
- `apply_*`、`promote_*`、`install_*`、`repair_*`：可能修改存档、安装目录或资源，必须先核对输入和目标。
- `prepare_*`、`launch_*`、`run_*`：可能启动游戏或服务器，只用于明确选中的开发副本。
- `tools/java/`：与原生游戏数据、模型和机械状态对应的辅助入口。

不要批量执行全部脚本。历史工具通常依赖某次本地施工的清单、原始存档或检查记录，不能直接用于当前玩家存档；共享导入模块也可能位于同一目录。可重建输出写入已忽略的 `artifacts/`，依赖写入 `.Codex/`，交付包写入 `delivery/`。
