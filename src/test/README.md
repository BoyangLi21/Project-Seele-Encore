# 回归检查

`src/test/java/` 中的检查使用 Java `main` 入口和显式断言。Gradle 的 `test` 任务不会自动发现并运行这些入口。

## 默认构建会运行什么

`gradlew build` 经由 `check` 执行 [build.gradle](../../build.gradle) 中注册的 `verify*` 任务，涵盖：

- 姿态过渡与采样时钟、战斗运动、膝部支撑；
- 足底接触、刚体精度、竖向运输扫掠、方块碰撞合并；
- 网格 JSON、姿态快照与视频编解码；
- 生物群系缓存及主线程约束、空间索引、导视与交通、GeoFront 高度。

可以用 `gradlew check --dry-run` 查看任务列表，或单独运行一个任务，例如 `gradlew verifyEvaPoseTransition`。没有配置额外夹具的检查不会因文件名含 `Test` 就自动执行，不能把 `build` 成功写成这里所有场景均已通过。

`verifyCityRelocation` 检查楼体平移后原身份、非位置字段和库存旅程选择。需要核对冷施工候选时，传 `-PcityRelocationCandidate=<候选目录>`，会将实际前后拓扑及原账本送入生产解析器；不启动游戏、不修改存档。默认构建不再运行旧资源／机体指纹比对；高度扩展检查直接比较所需方块状态，不计算哈希。

## 需要专门输入的检查

其余入口包含机械目录、原机机械任务与保存状态、机体网格和渲染生命周期检查。有些需要显式 JSON 参数，有些需要 Forge 环境、私有原始网格或本机资源清单。保留这些入口是为了对应问题的复现与诊断；是否参与默认构建以当前 `check --dry-run` 为准。使用前阅读各自的 `main` 参数和前置条件，不向默认构建强塞私人存档依赖。

`resources/physics/` 保存已入库的回归夹具，仍由现有任务使用。游戏画面、操作手感、真实设备联锁和长时间稳定性需要另外的原生检查及人工复核，不能用纯 Java 检查替代。
