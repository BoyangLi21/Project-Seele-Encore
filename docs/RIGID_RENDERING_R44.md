# R44 机库固定机械绘制诊断

2026-10-01，固定相机 `(48.5,-394,-251.5)`、FOV70、视距14、R44 光影，先记录实际 CPU 栈与显卡采样，再改绘制路径。没有降低模型面数或视距。

第一份 JFR 的 989 个渲染线程样本中，793 个经过 `RigidMachineryPartR44.draw`，占约 80.18%。主要消耗来自逐顶点字段写入及 Iris 每个四边形重新计算扩展属性。同期显卡整体利用率多数为25%～35%，约占用3.3GB显存。这个计数是采样栈比例，不是精确 GPU 绘制耗时；显卡统计也包含其他进程。

候选 `RigidMachineryGpuR44` 缓存完整固定几何，在现用实体／阴影着色器中提交 GPU 缓冲。缓存区分实际着色器对象、Iris 实体／方块实体／物品 ID、光照和镜像。镜像先烘焙到局部坐标再消除矩阵反射，避免法线计算与面序不一致。普通渲染沿用现有骨骼矩阵着色器，轮廓消费者保留原绘制路径。每部件最多16份状态缓存，资源重载释放 GPU 缓冲。当前仅由 `projectseele.r44RigidMachineryGpu` 开启，未默认晋级。

实际相机条件还发现一个测试错误：自定义维度的 `DerivedLevelData.setDayTime` 在本版本是空方法，因此在该维度设置6000并没有控制时间。已改用主世界共享时钟，拍摄期间暂停日时流逝，结束恢复原规则和应有的游戏时间；实际客户端日时必须等于指定值才允许截图。第一份未控制日时的记录只保留为诊断资料。

GPU候选该次快照记录114,022次绘制、347次上传、约141MB缓存顶点数据。数字是本次运行累计，不是每帧开销。18 FPS 也只是截图时读数，不能冒称整段平均、全图或最终性能通过。

上述对照的 FOV70 是设置值，未记录飞行 FOV 修正后的实际镜头；两组均使用相同旁观状态与选项，性能比较保留这一限制，不用这批图片作精确投影测绘。

后续 `space_photos/tv_cage_locked_lens_vanilla_v2/20261001_022427` 完成三机正面、后颈、侧面五张原生无光影图片，已实际查看。新摄影临时关闭飞行 FOV 效应，并从 `GameRenderer.getFov` 回读；五视角实际分别为68/68/68/58/58度。GPU路径为普通 `ShaderInstance`、36字节顶点，完整机械保留。截图瞬时100～117 FPS，未宣称平均性能；该批同时更改了前廊和机库姿态，不能直接拿它与旧造型的2 FPS作同条件倍数比较。

仍需开合／排液、资源重载、轮廓／阴影与最终安装副本检查。整个 TV 机库美术仍未通过，绘制速度提高不改变这项判定。
