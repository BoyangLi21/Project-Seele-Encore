# 街道设施与巨型机体（R64）

第 511 批在第三新东京市地表放了电线杆、电线、变压器箱、警报杆、避难所亭和静态红绿灯，共 31,789 格。这批设施会把初号机抬上杆顶，再把它卡在电线上，悬在街面以上约 7 格；萨基尔跨步只有 2 格，会被直接挡住。测试记录见 perf 2026-11-18 的报告。

这里有三样东西：

1. **细件按种类穿过**：巨型机体在任何高度都不和墙柱、栅栏、铁栏杆、锁链、灯笼、末地烛和避雷针这类细件碰撞。全城、两种城市状态都有效，不用任何数据。
2. **整块部件按清单穿过**（`street_pass_r64.json`）：变压器箱、警报喇叭顶、红绿灯灯头、避难所亭是整块的混凝土和石头，按种类分不出来（城里的楼也用这些方块），所以列在清单里。
3. **城市降下时收起设施**：把这批设施加进现有的街面设施表 `battlefield_r21.json`。城市停稳在降下（战斗状态）后，设施换成空气；升城前放回去。

## 谁能穿过，什么时候

- **哪些机体**：初号机这类 EVA（`EvaObstacleCollision.ignores`）、使徒（实现 `Angel` 的实体）、量产机（`EvaSmallObstacleMixin`）。人、车辆和其他实体照常碰撞。
- **细件**：`EvaObstacleCollision.thin`。玻璃板不在内：它和铁栏杆是同一个类，城里有整面玻璃板墙，机体不能从墙里穿过去。
- **以前的规则**：细件只在"脚底上下 1.75 格以内"可以穿过，而这个范围跟着脚走。机体踩上杆顶以后，杆子在它脚下一会儿变软、一会儿又变硬，它就卡在电线上来回弹。下午武器楼测试里"机体在 y 89 拿不到枪"就是这个现象。现在细件在任何高度都穿过，这个问题就没有了。
- **清单里的格子**：只有当时的方块是清单 `blocks` 里列的一种才穿过。地图以后在这一格盖了别的东西，这一格就恢复碰撞。
- **照常碰撞的情况**：后勤锁定和出击过程中的机体照常碰撞，和原来的规则一样。
- **跟着生效的地方**：新旧移动模型画脚时找地面、斜坡探测、贴墙姿势都经过 `EvaObstacleCollision.ignores`，所以脚不会再踩到杆顶上，也不会把电线杆当墙。
- **两处没跟着生效**：`EvaUnit01Entity` 里的 `dropAtR64`（新模型的边缘探测）和 `EvaTerrainSupport.height`（趴下时的地面）各自做射线，没有经过这个规则。这次没改这两个动作文件，影响是趴在杆子上时贴地面的姿势可能参考杆子。

## 可穿过清单

代码：`world/StreetPassR64`（读清单、发给客户端、查询）、`world/StreetPassCellsR64`（按 16³ 区块存的位图，以及发送用的压缩格式）、`network/ClientboundStreetPassR64`。

- **客户端**：玩家驾驶时，机体的移动在玩家客户端上算，所以服务器在玩家登录、换维度、重生时把清单发过去。3.2 万格编码压缩后约 3 KB。网络协议升到 82。
- **服务器读取时机**：开服后第一次用到这个维度时，读世界根目录的文件。文件改了要重开服务器才生效。
- **清单坏了**：日志写一行错误，然后当作没有清单，机体照常碰撞。

```json
{"schema": "projectseele.r64.street-pass.v1", "dimension": "projectseele:geofront",
 "blocks": ["minecraft:andesite_wall", "minecraft:chain", "..."], "count": 31789,
 "cells": [x, y, z, x, y, z, "..."]}
```

## 收起设施

`BattlefieldR21` 原来就有这个机制：城市停稳在降下后，把表里的格子换成"收起"的方块，升城前放回。工具会把第 511 批的格子加进这张表：展开时是它原来的方块，收起时是空气，告示牌连同文字一起记下。

这次还修了一个顺序问题：

- R45 城市收到升城请求后要先排队，等几刻或更久才真正起步。
- 排队期间，旧的城市记录仍然写着"停在降下"，于是刚放回去的设施又被收了一遍。城市升起后，这些设施（原来那 5,066 格）都不在。
- 现在 `BattlefieldR21` 还要看 R45 城市自己的状态，城市停稳在降下时才收。

**扩展后的表只能配有这个修正的包一起用。**

## 第一战行军迈不上路缘

`SurfaceAngelAssaultR52` 让萨基尔沿第一战路线走时，AI 是关着的，每刻只做水平移动。这样实体一直不算"着地"，而原版的抬步要求着地，结果它连 1/8 格高的路缘坡都迈不上。TrafficCraft 修路以后，路线上 z=36 就有一排这样的路缘：即使街道设施都能穿过，它也会停在 z≈27。

现在行军的一步抽成了 `marchStep`：步行的使徒每一步都带一个和一刻重力相当的向下分量（0.08 格），这样它站在地上，能像正常走路一样抬步。飞行的水天使不变。

路线北口的 3 丛矮树和路上的 2 盏路灯（磨制玄武岩柱，4 格高）也挡萨基尔，另有一份移除清单交给写入会话，不在本分支里。

## 怎么做清单（写入会话，世界停着）

```
python tools/street_pass_cells.py --world <世界> --rows E:/eva-map-buildings/plans/t4-street/rows.json --out <新目录>
```

输出四个文件：

- `street_pass_r64.json`：复制到世界根目录。
- `battlefield_r21.json`：覆盖世界里的同名文件（收起设施）。
- `cover_rows.json`：世界正处于"降下、设施已收起"状态时才有内容。用 `tools/write_deep_cells.py --allow-block-entities` 写入，让世界和表一致。
- `report.json`：统计。

规则：

- 设施行里的格子，只有世界里还是那一行写进去的方块才会收进清单。被拆掉或改过的自动跳过，例如武器楼门前清掉的 152 格。
- `--extra <文件>` 可以再列几列别的小东西让巨型机体穿过，格式见脚本说明。现在没有用到。

map-buildings 以后改动设施，要重新跑一次这个工具。

## 以前就有、这一轮不改的

- 城市升起时，大街两排楼之间只有 21 格宽，初号机 17 格宽。走着会往一边偏 2–3 格，爬上楼的裙楼（例如 83 号楼：先踩上 (21, 86, 11) 的青色陶瓦，再上 (22, 101, 12) 的石英台阶），一共被抬高约 20 格，然后被楼身挡住。
- 城市升起时，趴下的机体在大街里转不开。
