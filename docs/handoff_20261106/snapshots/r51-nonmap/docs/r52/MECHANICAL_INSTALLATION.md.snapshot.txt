# R52 Root 原机械安装

`NervRootAssemblyInstallationR52` 是生产入口。命令由运营权限2保护，显式提供实际世界根目录下的 bundle：

```text
/execute in projectseele:geofront run nerv r52 install r52/assembly_installation.json
```

bundle/组件引用拒绝绝对路径、`..`、跨世界文件、改动的 SHA 和 design 状态。目录、机械和航空文件先完整解析，才验证真实原 actor/轨道/基础/门/模型来源并 commission。任何未加载、source不符、物理阻挡或不完整安装保留 claimed 状态、保持原位，不进入旧坐标修复或重新生成原演员。

`assembly-installation.example.json` 是最小完整**结构示例**，`status=design`，全零 hash 明确表示待 Root填写；生产入口会拒绝它。它不包含任何地图坐标或可自动落地的默认文件。严格结构见 `assembly-installation.schema.json` 和 `mechanical-owner.schema.json`；Java parser 继续验证结构schema不能表达的物理关联、44层/90947液格、十态同footprint/唯一阶段、测得单位quaternion和完整原UUID。

指纹生成顺序：

1. Root 完成 ground directory（包括 native runtime bindings），计算 `NervRouteDirectoryR52.parse(document).fingerprint()`。目录自身不写这个hash，且不嵌引用它的机械/航空manifest。
2. Root 机械 owner 和独立 air manifest 引用该 fingerprint/epoch。总安装bundle也引用同一 fingerprint；每个 `file` 的 SHA 是该最终文件**原始字节** SHA-256，与 directory fingerprint 两者用途不同。
3. 安装入口保存原解析目录对象；air以独立已验参数传入，与该对象和同一 broker pool接通。不会把air加进已签名JSON后重新解析导致hash变化。
