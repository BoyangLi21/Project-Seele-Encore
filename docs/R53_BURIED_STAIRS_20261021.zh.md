# 楼梯埋入地板的入口修复

用户指出首级楼梯陷在地板里。这是外观和收口缺陷；“人体能通过”不能代替首级完整露出。上一批将15个较高地面样本归为落点误差的判断不完整，现由本记录纠正。

## 修前与范围

使用当前实际试玩的 `artifacts/r53_repair_20261015/client/saves/SEELE_R53_WORLD`。`buried-stairs1021/frozen` 冷冻两份实际区域文件及原生碰撞目录，完整扫描 X−16..90、Y−560..−350、Z230..345 内19段完整楼梯、344个踏步；短梯和装饰共45组另列，没有按通路许可自动改造。

新增诊断比较楼梯首级的低半踏面与实际前方地面高度。原图检出5段楼梯、15个首级方块：

- X3／56、Y−528、Z266..268，两段相向白梯。
- X5／55、Y−486、Z268..270，两段相向白梯。
- X5..7、Y−458、Z301，白色长梯入口。

原首级最高点与前方地面齐平，低半踏面却低半格，形成埋阶和凹槽。`native-before/screenshots/stair_0..4.png` 是五处原生画面，均已实际查看。检测首先在冻结原图检出缺陷，再生成差量。

## 修复与检查

`tools/repair_r53_buried_stair_entries.py` 将这15个首级方块改为相邻的原地板材质。上方梯段、楼层、三格宽通道、围墙和护栏保留，地板接到下一个完整踏步；没有下降整片房间地面或搬动楼梯。

1125个原生碰撞形状人体采样检查覆盖五段入口的三条通行带及横向偏移。修前存在半格下陷，修后连续剖面无下陷、相邻升高不超过半格，人体净空通过。实际副本重新测得19段、329个踏步，无同类埋阶；删去的15个阶梯方块已成为地板。该结果仅覆盖上述扫描范围和完整梯段，不表示全图美术已获认可。

精确旧状态和 NBT、逆向差量、冷区域备份及受保护文件哈希保存在 `checked-plan`。安装时维护静态缓存没有对应单元；玩家、实体、交通、任务和导航文件未被施工写入。

冷启动后的 `native-after/screenshots/stair_0..4.png` 五处实景均已查看，入口地板平整衔接。最终冷回读与冻结原图逐格比较，仅有计划中的15格差异；五份导航缓存哈希相同。远景0/4分区从实际存档完整垂直方块／生物群系列重建，4096列全部核对一致，证据为 `FINAL_DELIVERY.json`。取景结束按原生登乘恢复原初号机和插入栓，300 HP、占用座位和 PARKED 状态已回读。

首批楼梯施工时同时存在新步枪独立候选；该武器后续完成交付，记录在 `R53_PELLET_RIFLE_20261021.zh.md`，不与地图验收混算。

## 两段短梯补查

初次完整梯段检测将不足三级的构件单列，后续对这45组构件增加同样的首级诊断。仅检出两组三格宽的短白梯：X7／52、Y−514、Z263..265。`short-native-before` 两张原生画面确认这是原人行通路，非座椅或台面，均存在相同地板埋阶。

诊断只报告问题，不凭检测结果授予施工许可。明确到上述六格后，`--short-only` 精确修复入口；450个全宽人体样本通过。旧状态、NBT、区域冷备份和逆向差量保存在 `short/checked-plan`。

两处冷启动实景 `short-native-after` 均已查看，露出的首级接到平整地板。`short/FINAL_DELIVERY.json` 冷回读仅有计划中的6格差异，19段完整梯及45组短梯／装饰均无该埋阶诊断；4096列远景几何与生物群系全部一致，五份导航哈希保留。原初号机、玩家和插入栓身份、300 HP、PARKED和占用状态已恢复。两批合计七处、21格，1575个人体样本，不扩大为全地图或所有其他楼梯问题通过。
