# EVA 模型／骨骼／动作整体重建（Claude 负责，2026-11-01 起）

分工：Claude 负责四台 EVA（零号机、初号机、二号机、三号机）的模型、骨骼、动作、持武器与使徒处决；Codex 继续负责地图。

## 为什么要整体重建，而不是再修补

历次被否定的问题（"上下半身像分别播放"、"甩胳膊"、"越来越怪"、"先纠正骨架与变换"）都来自同一个结构：
- `EvaBodyPose.sample` 叠了约 40 层补丁，客户端 `EvaPoseGraph` 又叠十几层，每层修改上一层的结果；
- 三台 EVA 的源模型约 4k 三角形，按 27 个刚体部件挂在骨骼上，只在缝合处做双四元数过渡；
- 零／初／二号机骨盆转轴（y=91px）低于髋关节（y=115px），骨盆一转髋部就横向甩出；没有脚趾骨。

继续逐层修补只会重复以前的结果，所以改为两条主线：

1. **Blender 是唯一真源**：骨骼、动作、双人动作都在 Blender 里制作和检查，再烘焙成运行时直接读的数据。骨骼命名和 pivot 约定与现有游戏兼容，碰撞、武器挂点、命中判定不用改。
2. **运行时只有一条播放路径**：新包 `com.projectseele.anim`。只要动作包覆盖当前状态，就由它持有全身姿态，服务端和客户端采样同一份数据（命中体、武器挂点与画面一致）。后处理只保留少量明确的步骤（脚部 IK、瞄准、武器双手 IK），不再层层修补。不覆盖的状态自动回到旧路径，切换时由连续性守卫（0.22 秒残差衰减）消除跳变。

## 工具链（`tools/motion3/`）

| 文件 | 作用 |
|---|---|
| `bvh.py` | BVH 读取与正向运动学 |
| `evarig.py` | EVA pivot 骨骼的正向运动学（与 `EvaBodyPose.Sample.matrix` 完全一致） |
| `retarget.py` | 动捕 → EVA：躯干和四肢方向取自关节位置，扭转取自中立帧标定后的旋转差，腿部用双骨 IK 保持落脚点 |
| `build_motion_pack.py` | 步态周期提取（左脚触地到下一次左脚触地）、原地化、接缝过渡、60Hz 重采样、EVA 姿态风格化、导出动作包 |
| `blender/seele_lab.py` | 在 Blender 里重建运行时的 EVA 骨骼和网格（单位朝向的 pivot 骨骼，姿态矩阵与游戏一致） |
| `blender/render_pack_clip.py` | 把动作包里的片段渲染成序列总览图，用于离线检查 |

动作包 `seele_motion_pack.json` 放在客户端的 `projectseele-local-maps/`（私有运行数据，不进公开仓库）。没有动作包时运行时完全走旧路径。

## 数据来源与许可

- Bandai Namco Research Motiondataset 1/2：CC BY-NC 4.0（2023-07 起去掉了 ND）。giant 风格的走、跑、冲刺用于步态。非商业项目可用，需署名；衍生数据不能按 MIT 发布，所以动作包作为私有运行数据分发。
- CMU Graphics Lab：可复制、修改、再分发。
- Quaternius Universal Animation Library 1/2：CC0。
