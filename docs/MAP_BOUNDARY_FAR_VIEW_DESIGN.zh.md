# 地图边界和远景设计（F1 海、F2 山）

负责人原话见 [R62 验收反馈](R62_ACCEPTANCE_FEEDBACK.zh.md) 的 F 节：海的一侧无论走多远都是大海，海岸线按相模湾一带的真实地图；其他边界是用噪声生成的绵延高山，不能有复制粘贴感；Distant Horizons 里也要看得到。本文是方案和样张，**没有写正式世界**。定了以后由地图会话执行写入。

## 结论

1. **用生成器做，不离线写进区块。** 只改 GeoFront 维度现有生成器 `projectseele:geofront_bounded` 在实测范围以外那一段（`HakoneSurfaceField` 里的 `exterior()`）。海岸线以外一直是海，其余是噪声高山，公式对任何坐标都成立，走多远都一样。已保存的区块和实测地形一格都不变。
2. **远景单独烘焙。** 正式客户端的 Distant Horizons 设置不变（只画已有数据），打包前在副本上开远处生成，把外圈烘焙进远景库，随世界一起发布。
3. **正式世界只删不写。** 唯一要动的是地图外早先生成的零散区块（东北长带等），删掉以后它们会按新生成器重新生成。

## 1. 现在地图四边在哪，哪一侧是海

坐标都是方块坐标，x 向东，z 向南，比例 1:4（`tools/templates/hakone/geography.json`）。

| 范围 | x | z | 说明 |
|---|---|---|---|
| 已保存核心 | −3392 ~ 4512 | −2336 ~ 1600（西半边到 2848） | 165,166 个区块 |
| 实测地形（国土地理院 DEM） | −1982 ~ 4386 | −1548 ~ 3720 | 经度 138.92–139.20、纬度 35.14–35.33。矩形里没保存的地方，生成器也已经按真实地形生成 |
| 东北长带 | 约 2000 ~ 7424 | −2400 ~ −7872 | 38,891 个区块，早先飞行时生成的原版地形，就是执行顺序里记的"远景假墙" |
| UN 新址 | 544 ~ 1184 | 3808 ~ 4256 | 海上填海区 |
| 西南零散块 | −4256 ~ −1888 | 928 ~ 3232 | 几块共约 4,100 个区块 |

**海只在东南。** 实测海岸从汤河原（2360, 3720）经真鹤、小田原到国府津（4386, 78）。所以东边界南段、南边界东段面海；北边界、西边界，以及东边界北段（往大矶方向的陆地）、南边界西段（伊豆半岛）都是陆地。

**实测矩形以外现在是什么：** 原版噪声地形，海岸只是两条直线（x > 4386 或 z > 3720 就压成海）。客户端远景只画已保存区块，所以地图外要么什么都没有，要么是东北长带那种侧面看像墙的旧地形。

## 2. 海岸线用什么数据

- **实测矩形内：** 已经是真实海岸，来自现有地表场 `hakone_surface.bin.gz`（国土地理院 DEM 和最适化矢量，已在 [ASSETS](ASSETS.md) 署名）。
- **矩形外：** 用同一来源延伸，署名不变。范围东到三浦半岛城岛（经度约 139.62），南到伊豆半岛石廊崎（纬度约 34.60），北和西只需要确认是陆地。建议下载国土地理院 DEM 瓦片 z12（每像素约 31 m，即约 8 格），经度 138.8–139.7、纬度 34.6–35.5，约 12×12 = 144 块，约 5 MB。**下载要负责人同意**。
- **更远的地方：** 三浦以东、石廊崎以南一律是海（太平洋）；北、西一律是山。
- **样张里的海岸：** 是我按公开坐标手标的 21 个点（伊豆东岸：石廊崎、下田、稻取、城崎、伊东、宇佐美、网代、热海；湘南：国府津、二宫、大矶、平塚、茅崎、江之岛、镰仓、逗子、叶山、城岛），只用来出图，不进正式方案。

## 3. 外圈地形怎么来

| | A 生成器（推荐） | B 离线写进区块 |
|---|---|---|
| 无尽 | 天然无尽 | 只到写入范围，再往外还是原版噪声 |
| 和地图衔接 | 从已有地面平滑起坡 | 同样可以，但是要另写一套离线工具 |
| 正式世界 | 不写方块 | 写入约 48 万个区块 |
| 磁盘 | 只有远景库变大 | 区域文件约 +2 GB，远景库同样变大 |
| 以后改样式 | 改代码，删掉外圈区块和远景重新生成 | 全部重写 |

**A 的具体做法**（样张已按这个做）：

- **接口：** `HakoneSurfaceField.sample()` 在已保存或实测的列上混合权重为 0，完全不受影响；只在权重大于 0 的外圈，把原来的 `exterior()` 换成新的外圈地形。
- **"已知地面"只认两样：** 实测矩形，加上已保存的区块（不含要删的东北长带）。其余一律交给新地形，不再用现在的混合权重文件。原因是样张时发现，现有混合权重把实测矩形南边以外、地表场网格以内那条带（z 3720 ~ 4238）也当成了已知地面，用的是边缘一行重复拉出来的高度，远看是一排竖条纹的墙。
- **从已有地面起坡：** 离线算一张网格（8 格一格，约 0.4 MB），记录每个位置到最近已知地面的距离，以及那里的高度。新地形从那条边开始，900 格内平滑升到目标高度，所以保存区边上不会冒出墙或断崖。
- **海：** 用到海岸线的带符号距离区分海陆。海面 y−82（就是现有的 `SEA_Y`）；海底从海岸往外加深，最深到 y−120（世界底是 −128，再深写不下）。可选沙滩或礁石两种海岸。
- **山：** 先做域扭曲，再叠脊状多重分形噪声，种子固定，不平铺、不会重复。顶层材质按高度和坡度选：草、陡坡露石（整 4 层）、高处积雪。
- **默认开关：** 样张阶段用 JVM 参数 `-Dprojectseele.outerBoundary=...` 打开，不开就是原来的行为。正式实现改成写在维度配置里，GeoFront 默认开启。
- **已有区块不会自动改：** 东北长带、西南零散块，以及核心边缘没生成完的区块（第 151 批采集里有约 7,000 个不是 FULL），都要删掉让它按新生成器重新生成。删之前列清单、做备份。

## 4. 要多宽、写多少格

- 项目的远景半径是 `lodChunkRenderDistanceRadius = 192` 区块，即 3,072 格。所以在地图任何位置往外看，要看到外圈山海，外圈要有约 3 km 宽。
- 以已保存核心的外包矩形（x −3392 ~ 4512，z −2336 ~ 2848）向外扩：

| 外圈宽度 | 范围 | 新增区块 |
|---|---|---|
| 3,072 格（推荐） | x −6464 ~ 7584，z −5408 ~ 5920 | 约 48.2 万 |
| 2,048 格 | x −5440 ~ 6560，z −4384 ~ 4896 | 约 30.2 万 |

- 这些区块在 A 方案里**不写进正式世界**，只进远景库；玩家真走过去时，服务器当场用同一个生成器生成，和远景一致。

## 5. 对远景（Distant Horizons）的影响

- **现在：** 客户端是 `distantGeneratorMode = PRE_EXISTING_ONLY`、`enableDistantGeneration = false`，只画已保存区块和随包发布的远景库。地图维度远景库 247 MB，折合每个已保存区块约 1.5 KB。
- **改生成器以后要单独重建：** 在副本上把 DH 设成 `SURFACE` 远处生成，沿外圈布视点绕一圈，DH 用同一个生成器算出远景数据（不存区块）。完成后把远景库装回正式世界，客户端设置不变。
- **远景库会变大：** 按每区块 1.5 KB 估，3 km 外圈上限约 +0.7 GB，2 km 约 +0.45 GB；海面数据简单，实际会小一些。样张实测见第 8 节。
- **烘焙用的机器要够内存：** 样张时堆给 6 GB，DH 渲染线程内存溢出了 78 次；烘焙机建议堆 9 GB 以上，并且单独占用机器。
- **样张没能拍到 DH 画面：** 我的隔离客户端里 DH 能生成数据（远景库在增长），但一块远景都没画出来，连随包烘焙好的地图远景也没有；关掉自带光影包、只画远景模式都试过。地图会话现有的远景烘焙流程也只按远景库覆盖行数验收，不截图。所以外圈进远景这一步，要在烘焙阶段用覆盖检查确认，并请负责人在自己的客户端里看一眼。

## 6. 对磁盘、内存和服务器加载的影响

- **磁盘：** A 方案世界区块不增加，只有远景库 +0.45 ~ 0.7 GB（发布包相应变大）。B 方案按现在每区块约 4.1 KB 算，3 km 外圈区域文件约 +2 GB，另加远景库。
- **客户端内存：** 基本不变，DH 按需从库里读。
- **服务器：** 只有玩家走进外圈才会生成。现有生成器每个新区块先跑一遍原版噪声（高度 992 格）再覆盖，比较贵；正式实现时外圈直接按高度填方块，跳过原版噪声，烘焙远景和玩家探索都会快很多。

## 7. 建议的写入顺序和分批

负责人定了样式和宽度以后：

1. **数据和代码（main，不碰世界）：** 下载海岸数据（需同意），生成海岸线和距离网格资源；生成器正式实现，GeoFront 默认开启，外圈跳过原版噪声；在副本上实测接缝和四个方向。
2. **地图会话删旧外圈区块（正式世界）：** 东北长带 38,891 个、西南零散约 4,100 个、核心边缘未生成完的区块。每批先备份，删完读回。
3. **副本上烘焙外圈远景，分四批：** 北（山）、西（山）、南（海和伊豆）、东（海和湘南）。每批检查覆盖缺口为 0。
4. **装回和发布：** 远景库装回正式世界，小地图重新烘焙；放在世界写入全部完成以后、打 R63 之前（和任务表顺序一致）。

## 8. 样张

**怎么做的：** 原型在分支 `wip/f12-boundary-prototype`（`OuterBoundaryTerrain.java`，默认关闭）。生成器的高度由同一份 Java 代码离线算出，再用透视高度场渲染：地图内用实测和已保存的地面，外圈用新地形，8 格分辨率，看到 7 km 远。

**为什么没用游戏截图：** 这台机器同时开着 5–6 个别的会话的客户端，外圈区块在游戏里生成得极慢：等 3 分钟，32 区块视距里只出来几块海。DH 又画不出来（见第 5 节）。所以样张不是游戏截图，建筑、树和水面细节都没有，只看地形样式。

**三组变化**（海岸两种，山三种）：

| 组 | 海 | 山 | 外圈最高 / 九成高度 |
|---|---|---|---|
| v1 | 沙滩：海岸后留 340 格平原再起山 | 尖脊：脊状噪声，峰起伏适中，零星露石 | y280 / y176 |
| v2 | 礁石：山在 180 格内落到海边，近岸有海蚀柱 | 圆润：大块山体，高处有成片雪原 | y300 / y209 |
| v3 | 沙滩 | 层叠：贴着地图是低山，越往外越高，远处是尖峭雪峰 | y300 / y208 |

所有组都有千米尺度的高山区和宽谷交替，同一段地平线不会出现同样的山形。

**七个视角**（俯视图上标了 A–E）：A 小田原海岸往东北看湘南海岸；B 小田原上空往南看真鹤、伊豆和外海；C 西边界上空往西；D 北边界往北；E 西北角高空往西北；C、D 近景是站在边界上平视往外看。

**文件**（全部在 `E:\eva-map-edges\samples\`）：

- 一页看完一组：`v1-sheet.png`、`v2-sheet.png`、`v3-sheet.png`（七个视角加俯视图）
- 单张：`v?-A-sea-east.png`、`v?-B-sea-south.png`、`v?-C-west.png`、`v?-D-north.png`、`v?-E-northwest-high.png`、`v?-C-near.png`、`v?-D-near.png`、`v?-overview.png`（? 为 1、2、3）

**海和山可以分开选：** 比如 v3 的山配 v2 的礁石海岸都可以。

## 9. 已知限制

- 样张海岸是手标点，正式方案要换成国土地理院数据。
- 样张是离线渲染，不是游戏截图；正式实现后要在副本上进游戏复查接缝和材质。
- 外圈山上没有树：GeoFront 用的固定生物群系没有地物。要树的话，外圈改用带树木地物的高地生物群系，远景颜色也会变深。
- 海底最深只能到 y−120。
