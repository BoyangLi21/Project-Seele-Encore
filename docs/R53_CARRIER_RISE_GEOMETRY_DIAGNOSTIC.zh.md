## 已证明的问题

源：当前 `CarrierAssemblyR53.Profile.frame`、`CarrierRearGuideR53.Hardware.partsAt`；三机原根位来自 `rear-rail1022/ACTUAL_ROUTE_SAMPLES_B.json`。原架使用完整 8,727 个用户提供的三角面及现有工程附件。冻结世界位于 `F:/eva/artifacts/r53_repair_20261015/rear-rail1022/frozen`。

报告：`NATIVE_RISE_V16_FLEET.json`、`NATIVE_ORIGINAL_RISE_FLEET.json`，均在上述 `rear-rail1022` 目录。123 帧是有限反例诊断，不是连续运动通过证明；计数也不是独立缺陷个数。

初号机示例：rise=1 时 body 与 `(22,-1063,313)` 的 `nerv_floor_panel` 相交，deck 与 `(18,-1063,314)` 的 `iron_block` 相交。rise=0 时 body 已位于 `Y≈-1115` 的实心深板岩中。不能把这些方块统称为可忽略的门代理。

原因有两层：

1. `CarrierAssemblyR53` 把非 deck 源件放到根位以下 64 米，再连续升至地板上；新增背轨复制同一偏移。原三机库地板明确保留，退休地坑不能重开。隐藏 rise=0 的渲染不等于存在实体收纳空间。
2. `import_carrier_mk2_r53.py` 使用 `Y_OFFSET=-4.0078125`。源 deck 最低 `-4.0078125m`。原三机足底最低均约 `0m`；在低足底顶点处向托板实三角面射线，托板主要顶面约 `-0.111328m`、底面约 `-3.172852m`。单纯把顶面抬至足底，仍有约 `3.061524m` 厚度穿过完整楼板，且现状有约 11cm 的脚底间隙。保持有厚度水平托板、原脚底为零、完整楼板且不改变承载关系，不能靠一个平移同时满足。

## 接生产前必须一起解决的接口

1. 原 controller、三条通道和静态轨道坐标保持。承载姿态的机体、插栓、架上电源及支承使用同一个局部变换；不能只移动模型。脱离时必须转换为实际世界根位，不能视觉跳低 4.25m。
2. 原托板源面完整保留。实际脚垫需补足实测间隙，并证明三机低足底的有限面积接触。不能继续用 UUID/同根位代替承载证明。
3. 背部源焊点随原架升高，但既有轨道头世界位置须保持：可延长工程滑杆 4.25m，以相对承载基准的 `-4.25..+2.75m` 行程恢复原世界 `0..7m` 轨迹。套筒有限面接触、全部自交、原体附件及演员碰撞须重新验证，不能移动静态轨道迁就它。
4. 原插入栓仍在原 dock/原桥上登机；应验证现有 hoist 到抬高后 socket 的真实行程、吊点和全源扫掠，不能直接把桥、玩家与通道整体抬高。
5. PARKED 阶段的实际承载与固定 gantry 接触也要成立。若保持 EVA 旧脚底位置，不能先把整厚托板放到其腿中，再在整备时硬抬升；这是不同状态之间的真实部署问题，静态方块为零并未解决。
6. 当前原演员机构必须纳入检查。V17 在约 7.2m 的 `rear_r/ball_socket` 已确认撞原固定 gantry 柱，见下文；本候选不能豁免该演员。
