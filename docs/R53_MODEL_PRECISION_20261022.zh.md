## 三号机的确切输入与拒收原因

用户提供的 `evangelion-unit-03.zip` SHA-256 为 `2c04316f4980443e7a3342c21cfd4cccf238bd3384889a5377c29c8b3096632b`。嵌套 OBJ 含 4,627 个三角面，其中两份 718 面前臂/手对象的逐角位置、UV、法线完全相同。保留实际材质指向 `w03_001.png` 的那份，唯一表面为 **3,909 面：身体 3,191 面，前臂及手 718 面**。两张底色均为 512×512，另有 256×256 glow。该包没有另一套更高面数的身体模型，不能把它与百万面 Tripo UN01 源混为一谈。

旧 `bind_unit03_shared_rig_r53.py` 用 RBF 将身体拉到初号机固定关节，再将源卷曲手拉到初号机手绑定姿态。`candidate-v10` 的已有标定点两两距离缩放比从 30.8 到 65.6976，相差 2.133 倍，明确不符合统一缩放保留比例。`candidate-v11` 在这个变形体上使用通用背部穿孔和盖板，不能复用为新身体的合格背部方案。两者继续拒收。

本次生成 `model-precision1022/v1/unit03-source-preserved/`：

- 直接解析原 ZIP 内 OBJ，不从旧变形候选反推源表面。
- 统一缩放至模型高 192，比例 43.7386923，按现有模型约定将前向 +Z 转为 −Z；不做非刚性变换。
- 3,909 面全部保留；全部三角边长度只乘同一个比例，最大相对误差约 `2.05e-12`。UV 精确不变，法线反向换轴后逐分量恢复原值，原图片逐字节复制。
- 源手的卷曲和原背部表面完整保留，没有换手、打孔或生成盖板。
- `unit03_source_surface.npz` 是未绑定的交换基线，不是可安装资源包。原面序、材质索引和每对象面号可用于后续精确绑定/切分回溯。未来导出器必须显式处理自身换轴及绕序，不能对该中间文件盲目二次反射。

## 最小实施顺序

1. **保留三号机源表面，重标骨架。** 以本次统一缩放基线量出髋、膝、踝、肩、肘、腕和手指局部轴。复用初号机骨骼命名与父子关系，但不能照搬其世界枢轴。源手已卷曲，需记录各指原绑定基准，再施加动作增量，避免重复弯曲。
2. **初号机动作重定向及模型附属合同同批更新。** 按新肢长/绑定基准重定向动作、武器手掌接触、脚底支撑、眼睛位置和物理关节。旧 `stage_unit03_shared_rig_r53.py` 直接复制 rig1 的 stance/locomotion/gameplay 及 articulated physics 不能直接视为合格 rig4；即使凸包重算了，关节、绑定和接触也要一致。
3. **背部单独做真实几何匹配。** 从三号机原背甲标记量插栓轴、盖铰链及入口。不沿用 v11 的通用孔/盖；任何切分必须保留原表面与精确差量，检验关闭、开启、插栓行程和接电端口。
4. **临时演员原生验证后再替换 UN01。** 先查中性正背面、手近景及连续初号机动作，之后再核对原 UN01 实体槽、显示身份、任务/生命/玩家进度。不能安装旧变形候选，也不以离线面数通过替代画面。
5. **00/01/02 动态精度收尾。** 复用当前已证明相同的源/资源，逐部件对照实际提交顶点与绑定，重点覆盖替换手、腕接缝、背盖/内衬、腰颈及下颌。将显隐、蒙皮/关节错误和原作者低面拓扑分别记录；不为“增加精度”删除原面或引入新减面预算。

新工具为 `tools/audit_r53_model_precision.py`。完整资源哈希、源输入、比例负例和保留基线存于 `artifacts/r53_repair_20261015/model-precision1022/v1/`。模型和贴图只留私有工件，不加入公开代码仓库。此次关闭的是输入身份与可复用静态证据核对，三号机绑定/安装及三机连续姿态美术仍未关闭。
