# R66 使徒与作战章节扩充方案

分支 `claude/r66-angels`，基于 origin/main `fe3962a3`（R65）。负责人离开期间由项目审查会话推进。本文是方案，数值都是初稿，放进 `SeeleConfig`，负责人回来再定。

## 现状

章节目录在 `world/TvCampaignCatalog.java`，每个章节有 id、集数、标题、目标和 `playable` 开关。

| 章节 | `playable` | 实体 | 公开构建里看得到的模型 | 打法完成度 |
|---|---|---|---|---|
| 萨基尔（第 1、2 集） | 是 | `SachielEntity` | 方块拼的后备体型 | 完整 |
| 拉米尔（第 5、6 集） | 是 | `RamielEntity` | 原创八面体 | 完整（屋岛） |
| 夏姆希尔（第 3 集） | **否**，简报写着"等可再分发的夏姆榭尔模型到位后重做本战" | `ShamshelEntity` | 方块拼的后备体型 | 光鞭和横扫已有；没有失败和重试 |
| 迦吉尔（第 8 集） | **否**，另有 `preparationBlockerR52` 硬性挡住 | `GaghielEntity` | **没有**：只认私有网格 `gaghiel_r49`，公开构建里是隐形的 | 海上导演、咬合、舰炮（反射调用 SBW 炮）、核心判定、失败和重试都已有 |
| 以色列菲尔（第 9 集） | 否，目录里有条目 | `IsrafelEntity` | 借用萨基尔的后备体型 | 分裂与"5 秒内同时击倒"已有，没接进任何章节，也没接进围城事件 |
| 玛特里尔（第 11 集） | 否，目录里有条目 | 无 | 无 | 无，但屋岛的全城停电画面（`YashimaBlackoutR64`）可以复用 |
| 撒哈奎尔（第 12 集） | 否，目录里有条目 | 无 | 无 | 无 |

**流程上的坑。**
- `TvCampaignDirector.tick` 把萨基尔、拉米尔、迦吉尔以外的每个章节都当成旧的夏姆希尔战，会生成一只夏姆希尔。新章节必须先接进自己的导演，不能直接把 `playable` 打开。
- 章节没有"需要几台机体""站位"这些字段，这些散在各章节的代码和世界文件夹里的 JSON（`surface_angel_assault_r52.json`、`tv_encounter_sites_r45.json`、`tv_marine_site_r50.json`）里。这些 JSON 都是手工装进世界的，模组不会写。新章节的站位只写进测试副本，正式世界只出清单。
- `/seele sortie select` 的四个选项是写死的，新章节要加进去，`docs/COMMANDS.zh.md` 同步。
- 除了拉米尔（屋岛的驾驶舱复查），没有任何工具能从出击自动打到击毁，需要新写一个（见"测试工具"）。

**模型的红线问题。** 主客户端已装的 jar 里有私有使徒网格：`shamshel`、`israfel`、`sachiel`、`zeruel`、`gaghiel_r49`。`HybridAddonRenderer` 和 `GaghielRendererR50` 找到它们就会画出来。按规定拆包模型绝不使用、绝不入镜，所以这一轮涉及的每个使徒都换成原创的直连顶点渲染器，不再读任何 addon 资源。复查用的 jar 也会剔掉这些私有使徒文件，保证录像里不会出现。

## 优先级

按"对原作味道的影响 × 工作量"排：

| 顺序 | 使徒 | 原作影响 | 工作量 | 理由 |
|---|---|---|---|---|
| 1 | 夏姆希尔补完 | 高 | 小 | 章节和光鞭都在，补模型、原作打法和场地即可交 |
| 2 | 迦吉尔补完 | 高 | 中 | 海上导演、失败和重试都已有，但章节锁着，使徒在公开构建里是隐形的，必须先补模型 |
| 3 | 以色列菲尔 | 高 | 中 | 分裂机制已有；同步出招是双人联机的招牌玩法 |
| 4 | 撒哈奎尔 | 高 | 中偏大 | 全新使徒；三机冲刺接住是名场面，需要新的落点预测和合力判定 |
| 5 | 玛特里尔 | 中 | 大 | 依赖停电、内部电源和驾驶舱（和 lcl 交集最多），留到最后 |

## 1. 夏姆希尔补完（第 3、4 集）

**原作打法。** 夏姆希尔在城市上空低飞，以直立姿态逼近。两条光鞭从肩部伸出，能切开大楼和地面，挥舞时带出火花。初号机步枪打不穿 AT 力场，被光鞭缠住脚踝甩到山上，脐带被切断，内部电源只剩 5 分钟。真嗣冲上去，任光鞭贯穿腹部，用刀抵住核心直到它熄灭。

**我们怎么做。**
- **模型。** 新写 `ShamshelRendererR66`，直连顶点：
  - 扁平的长条节肢躯干，前端是带"肋板"的头部，腹面有一排短足。
  - 红色核心半露在胸腹之间，露核时肋板张开。
  - 光鞭沿用现有 `ShamshelWhipMotion` 的分段点，画成带辉光的扁带。
  - 不读 addon 资源。
- **AI 与攻击。** 保留现有低空追击和横扫，新增两招：
  - **缠绕甩投**：鞭子缠住机体脚踝，把机体甩出几十格，落地造成伤害，并有概率切断脐带。断缆后接到现有的内部电源倒计时。
  - **切地**：沿地面划出一道切口，切过的方块打碎，不进存档改动清单，只在测试副本里生效（见"场地"）。
- **核心与 AT 力场。** 现有 700 力场照旧，EVA 近战消耗力场。核心只在缠绕或横扫的收招窗口露出。刀插进核心后进入"抵住"状态，持续按住攻击键约 3 秒，核心熄灭才算击毁，对应原作那一刀。
- **EVA 方应对。**
  - 步枪只能打掉力场，打不出伤害。
  - 近身后用刀抵住核心，期间承受光鞭贯穿伤害。
  - 被甩飞后要爬起、找回步枪或直接拔刀。
- **场地。** 第三新东京市地表，沿用现有 `SurfaceAngelPlanR52` 的 shamshel 站位。切地和断楼只在测试副本里生效：正式世界的改动只出清单，R65 正式包之后再交写入。
- **接进作战流程。** 章节 id 不变（`shamshel`）。
  - 打开 `playable`，简报改成正式内容。
  - 补上失败（机体全部倒下、电源耗尽）和重试；现在旧路径没有失败阶段。
  - 首选地表路线（`SurfaceAngelAssaultR52`），它已经认 `shamshel`。
  - 胜利判定沿用 `seele_tv_shamshel_r24` 标签加死亡事件，血条的力场上限改读配置。
  - 刷怪蛋补进创造栏。
- **工作量。** 模型约半天；两招加核心抵住约一天；测试和录像半天。

## 2. 迦吉尔补完（第 8 集）

**原作打法。** 联合国舰队从香港运送二号机，迦吉尔在海中袭击。二号机穿着 B 型装备，在航母甲板之间跳跃。它被吞进嘴里，在海底撬开上下颚，两艘战舰冲进嘴里开炮，从内部打穿核心。

**我们怎么做。**
- **模型。** 新写 `GaghielRendererR66`，直连顶点：
  - 鱼雷形长身，头部是可开合的上下颚，口腔里有红色核心。
  - 尾鳍、胸鳍按现有 `swimPhase` 摆动，鳞片用分段环面表现。
  - 骨骼点（嘴、核心、颚铰链）完全沿用现有 `modelPointR50` 坐标，现有判定不用改。
- **AI 与攻击。** 现有的游动、咬、跃出、鳍扫保留，补两件事：
  - **吞入**：咬中后把机体拖到水下，机体进入"撑颚"状态，玩家连按交替键撑开嘴，撑开时露出核心。
  - **舰炮支援**：撑开嘴时，NPC 舰船（用现有船只或简单的原创舰体实体）向嘴里开炮，造成核心伤害。玩家也可以用步枪打进嘴里。
- **核心与 AT 力场。** 在水下张嘴时核心可被命中，其余时间打不到。
- **EVA 方应对。** 在甲板之间跳跃移动，站在甲板上射击。被吞后撑颚，撑开以后配合舰炮或步枪击毁核心。
- **场地。** 用现有 `TvMarineDirectorR50` 的海域。舰船甲板如果需要新方块，只出清单。
- **接进作战流程。** 章节 id `gaghiel` 不变。海上导演 `TvMarineDirectorR50` 已有生成、失败、重试和死亡判定，主要工作是：
  - 打开 `playable`，去掉 `preparationBlockerR52` 里的硬性阻挡。
  - 补完空着的 `cargoContactR50`。
  - 新增"拖到水下超过时限"的失败条件。
- **工作量。** 模型约一天；吞入和撑颚约一天；舰炮支援约半天；测试半天。

## 3. 以色列菲尔（第 9 集）

**原作打法。** 第一次交战中，二号机把它劈成两半，两半各自成为独立个体，互相弥补损伤后复原。之后真嗣和明日香同居练习，按音乐同步动作。第二次交战时，两台机体在 62 秒内以同一套动作攻击，最后同时踢中两个核心。

**我们怎么做。**
- **模型。** 新写 `IsrafelRendererR66`，直连顶点：
  - 细长的人形，肩部宽大，脸是一张面具状的平板。
  - 分裂前是一体；分裂后两个个体左右对称，各带一个核心，配色各取一个色调，便于区分。
- **AI 与攻击。** 现有分裂和"击倒后 5 秒内另一个也被击倒才算死，否则复原"保留，补：
  - **成对行动**：两个个体互相保持距离，交替进攻，一个受伤时另一个掩护。
  - **同步窗口**：击毁需要两个核心在约 1 秒内同时被击中（原作的同步踢）。现有的 5 秒窗口作为宽松档放进配置。
- **EVA 方应对。** 两台机体分别对付一个个体，同时出招。界面显示两个核心的同步计时，让玩家看出差了多少。
  - 联机时两名玩家各驾驶一台。
  - 单人时第二台由 NPC 驾驶，NPC 会按玩家出招的节拍跟招。
- **场地。** 海岸或市区地表，沿用现有的 encounter site 机制，新增一个 `israfel` 站位。
- **接进作战流程。** 新增章节 id `israfel`，要求两台机体（零号机外的任意两台，或初号机加二号机），胜利条件为两个个体都被击毁。
- **工作量。** 模型约半天；章节接入半天；成对 AI 和同步判定约一天；测试半天。

## 4. 撒哈奎尔（第 12 集）

**原作打法。** 撒哈奎尔在轨道上投下自身的一部分，测试命中精度，之后整个从天而降，要撞毁 NERV 总部。三台机体从不同方位冲向预测落点，初号机用 AT 力场接住，零号机和二号机赶到后一起撑住，二号机用刀刺穿核心。

**我们怎么做。**
- **模型。** 新写 `SahaquielRendererR66`，直连顶点：
  - 巨大的扁平眼状体，中央是眼睛和核心，两侧向外伸出手臂状的膜翼。
  - 下落时整体呈现透视远小近大，带红热的再入辉光。
- **AI 与攻击。**
  - **试投**：先向城市投下两到三块"碎片"，落地造成爆炸（打碎测试副本里的方块）。
  - **主体坠落**：在高空出现，给出一个随时间收窄的预测落区，大约 60 秒后坠地。
- **核心与 AT 力场。** 没被接住前打不到。接住以后，核心在使徒下表面露出，任何机体的近战都能命中。
- **EVA 方应对。** 三台机体从各自的出击口冲向落区。
  - 第一台到达的机体展开力场接住，进入"支撑"状态，支撑值随时间下降，需要第二、第三台加入才能撑住。
  - 撑住后，任一台都可以刀刺核心。
  - 时间到了没有接住，或支撑值归零，就判失败，坠地造成大范围爆炸。
- **场地。** 第三新东京市上空，落区在 NERV 总部附近的地表。试投和坠落造成的破坏只在测试副本里生效，并且和 perf 的城市破坏系统共用接口（见"交集"）。
- **接进作战流程。** 新增章节 id `sahaquiel`，要求三台机体，NPC 可以补位。阶段为 alert → approach（落区收窄）→ combat（接住后）→ victory 或 failure。
- **工作量。** 模型约一天；坠落、预测落区和支撑合力约一天半；测试半天。

## 5. 玛特里尔（第 11 集）

**原作打法。** 有人切断了 NERV 的主电源和备用电源，总部全面停电。三台机体只能靠内部电源，手动从发射井爬上地面。玛特里尔是一只长腿蜘蛛形使徒，从眼部滴下能溶解装甲的强酸。三台机体在通风井里被酸液压制，最后由一台引开、一台接住步枪，从下方射穿核心。

**我们怎么做。**
- **模型。** 新写 `MatarielRendererR66`，直连顶点：
  - 球形身体，四条细长多节的腿，腹面有多只眼睛，眼中滴出酸液。
- **AI 与攻击。**
  - 站在总部正上方，缓慢移动。
  - **酸液**：从眼睛向下滴，形成持续伤害的酸池，能腐蚀方块（只在测试副本里生效）。
- **核心与 AT 力场。** 力场较弱，核心在身体正下方，只能从下方射击命中。
- **EVA 方应对。** 作战开始即全城停电（复用 `YashimaBlackoutR64` 的画面）。
  - 机体不接脐带，只有内部电源，倒计时按配置。
  - 从地下通道上到地表，避开酸液，绕到使徒下方射击核心。
- **场地。** 第三新东京市地表和发射井出口。停电只影响客户端画面，不改存档。
- **接进作战流程。** 新增章节 id `matarael`。开始时强制所有出击机体处于内部电源状态（和 lcl 的电源、脐带设计对接）。
- **工作量。** 模型约半天；停电和电源约束约一天，主要是和 lcl 的接口；酸液和地形腐蚀约一天；测试半天。

## 新章节怎么接

以色列菲尔、撒哈奎尔、玛特里尔各写一个导演类，挂到 `TvCampaignDirector` 的开始、取消、重试和 tick 分支上，写法参照迦吉尔的海上导演：
- `TvEncounterRulesR45.handles` 加上新 id，阻止它们落进夏姆希尔的旧路径。
- 站位读 `tv_encounter_sites_r45.json` 里的新条目。
- 胜利统一走 `complete()`。
- NPC 驾驶员的打法写在 `NervPilotCombatR30`。

`StorySynchronizationR64` 里这些章节的同步率基线已经有了。

## 测试工具

新写一个复查类（`AngelSortieReviewR66`，只在开发构建里由 `-D` 开关启用）。它在 `SEELE_LAUNCH_REVIEW` 开头的一次性存档里执行：
- 选章节、开始作战、等机体出击。
- 驾驶机体逼近使徒，按该章节的要领打（步枪削力场、近身用刀、撑颚、同步出招、接住等）。
- 每刻截一帧，打到击毁就停，日志写 `angel_review_complete`。

出击段沿用 `EvaConnectedActionReview` 已有的真实出击（`launchReal`）。录像用每刻截图合成 60 fps 视频，放 D 盘。

## 数值初稿

所有数值放进 `SeeleConfig` 新增的分区（`shamshel`、`gaghiel`、`israfel`、`sahaquiel`、`matarael`），先按现有使徒的量级定：萨基尔 800 生命、900 力场；夏姆希尔 620 生命、700 力场；拉米尔 350 生命；以色列菲尔 720 生命、850 力场。每个使徒做完时，交审里列出所有新增和改动的数值。

## 交集

- **Fable（EVA 动作）：** 撑颚、支撑、甩飞后爬起、刀抵核心都需要专门姿势。先用现有的受击和抓取姿势顶替，交审里列出需要 Fable 补的姿势清单和接口（状态从哪里读、持续多久）。
- **lcl（驾驶舱、电源）：** 断缆后的内部电源倒计时、玛特里尔的强制内部电源、停电时驾驶舱画面。只读写现有的电源状态，接口写清楚。
- **perf（城市破坏）：** 光鞭切楼、撒哈奎尔试投和坠落、玛特里尔酸液的方块破坏。先只在测试副本里直接打碎方块，交审里写明调用点，以后换成 perf 的城市破坏接口。

## 每个使徒的交付标准

1. 完整构建通过，80 项检查通过。
2. 在测试世界副本（复制 `D:/eva-codex-pack/source-world`）里，从出击打到击毁。
3. 60 fps 录像，放在 D 盘，录像里没有任何私有模型。
4. 写明对应原作的哪些场面，以及哪里和原作不符。
5. 列出新增和改动的数值。
