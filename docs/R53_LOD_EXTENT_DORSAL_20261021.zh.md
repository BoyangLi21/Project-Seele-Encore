# 远景空中平板与背部盖内衬

## 远景空中平板

城市上空的大块横板来自 Distant Horizons 2.3.4-b 的父区块合并。原生对照分别关闭原版云、DH 云和光影，横板仍在；关闭 DH 地形后消失。没有用增加雾、缩短视距或删除真实建筑处理。

`mergeInputTwoByTwoDataColumn` 在四个输入游标刚好用尽的那次循环，仍写入一个默认 ID 0 的高度采样，到下一次循环才退出。输入最高点之上因此多一层；本存档 ID 0 在相应缓存里指向基岩，继续上采样又会传播。这也解释了横板为什么有时披上云的阴影。

`DhColumnExtentR53Mixin` 将合并输出限制在四个实际输入列的最高端点内，裁剪时保留合法区间中的 ID、光照和高度编码。不是按地表高度截断洞穴。针对同一真实基础区块的 1024 次合并，修前全部多一层，修后及重启后最大额外高度为 0。

旧缓存另外处理：冻结当前实际世界的 SQLite 副本后，`audit_r53_lod_world_extent.py` 检出300个带有世界最高可建高度之外实体面的父区块。使用原生 DH DTO 和数据库接口清理这些区块；保留实际世界高度内的数据。注意该版本 DTO 的 `MinY` 为未使用的0，审计必须使用实际维度的最低高度−1344和最高高度320，不能拿 DTO 的0作为最低高度。

清理后的完整回读：

- 15948行中只有上述300个父区块的数据改变。
- 11916个基础区块未改变；所有区块的材质映射字节不变。
- 全部父区块在真实世界高度范围内的完整压缩前列数据哈希不变，包含光照。
- 世界高度以上不再有实体面。正常顶层空气填充可以保留。
- 原区块、实体、设备和导航不在本次缓存修改范围内。

重启后在相同相机位置检查4组云设置，原空中横板消失，远处城市仍显示。私有证据：`city-sky1021/` 中的 `before.sqlite`、`EXTENT_BEFORE.json`、`CLEANUP_NATIVE.json`、`EXTENT_AFTER.json`、两份合并探针和原生截图。此项只关闭已定位的虚假顶层，不能据此宣布整张地图的所有近远景接口已验收。

## 背部盖内衬

原机体处于服务架保留姿态时，渲染每帧恢复了骨骼可见性，但该分支跳过常规背盖处理，关闭的盖下内衬又被显示。现在把内衬可见性收敛到所有姿态共用的最终提交位置，铰链旋转仍由当前姿态所有者控制。

原初号机盖关闭、服务姿态保留的三个实机视角中，`dorsal_liner` 从实际提交网格中移除；其他所有零件的实际顶点逐值一致。没有删除模型源面。原生模型另外检查关闭→打开→关闭三次可见性，分别为隐藏→显示→隐藏，未删除开盖内衬。

私有证据：`plug1021/mesh-before-b`、`mesh-after`、`MESH_VISIBILITY_COMPARISON.json`。这不替代插入栓全流程、转移架模型和所有乘坐姿势的后续验收。
