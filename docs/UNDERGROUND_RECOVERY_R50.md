# R50 地下运输与原机接应

状态：2026-10-07，原地下平台真实回库、attempt13断电同原初号机机场闭环，以及attempt14有电准入/一次活CRUISE保存重登后的同原回库均有本轮实测。不是全程有电，也不计全部姿态/节点/NPC/中断阶段或美术通过。

本轮新增第41项目标：GeoFront内设一个重型运输机待命场；呼叫回收按原机体实际所在空域选择地表或地下航线。地下飞机把原载荷交给所属发射仓的外侧接应架，承载架再沿连续轨道进入后门和原机库。

## 首次错误的位置

旧地下回收入口把“完整双足平放”作为全部回收的前置。原生V弹出后，同一二号机仍在 `(72.5,-410,6.5)`，原插入栓正常落地；但此前断电保存的真实姿态有一只脚抬高约一米。它不是站位丢失，也不能通过强制改成站立来修复。旧路由还把未通过足底联锁的原机体转派了只接受露天空域的地表运输。

另一个独立问题是接应净空。飞机真实外包络为左右72米、前后60米，原后门平台上方与发射井外墙相交。飞机不能缩小碰撞或穿过外墙接机。实测候选将卸载点移到同轴 `Z100.5`，接应架保持原机身份，送回原 `Z6.5` 平台和 `Z-35.5` 下层床。

## 已实现的接应与运输

- 接应机械先采样原载荷当前全骨姿态，再取得机械控制；断电、损毁、俯卧姿态都不能在夹持前自动站起。
- 六组接触支撑先伸出固定，提升两米避开实际边栏，再连续整姿，最后落到原转移架姿态。整姿使用原关节长度与旋转，不拉长骨骼。
- 每步检查实际躯干、足部和手臂包络、原生方块碰撞形状、液体以及人员/设备。遇阻保持已接受的原位置、姿态和时钟；重新登录后继续，不做纠正瞬移。
- 没有新建替代EVA或插入栓，没有恢复健康、改库存或移动驾驶员。飞机交付与地面机械接管是独立原载荷交接。
- 客户端固定架姿态的条件改为“当前是否显示关机自由姿态”，与服务器共同姿态一致；关机标记本身不再让已经机械锁定的模型绕开固定架姿态。

实际原存档离线轨迹最先检出的错误是右脚在整姿第65tick增加了与 `(89,-410,5)` 边栏的重叠。加入先提升再整姿后，360tick轨迹没有新的固定块冲突，未知方块状态为0。这只证明此保存姿态下的固定几何轨迹；动态人员、网络同步和最终原生回库须另记结果。

证据：`artifacts/rebuild_r50/native_client/ejection_preflight/ground_receiver_solid_trace.json`；机场候选测量：`artifacts/rebuild_r50/underground_airport/receiver_initial_headroom.json`。来源世界只读，正式施工与原生测试世界的进度保持分离。
