项目展示名统一为 **Project SEELE: Encore**，源码仓库为 [Project-Seele-Encore](https://github.com/BoyangLi21/Project-Seele-Encore)。原 main 历史已迁移，旧 Project-Seele 仓库保留；新仓库的旧 mcp-bridge 分支已按负责人要求删除。

本轮按负责人最新要求立即停止继续扩展，收尾已有工作，交付可继续正常试玩的阶段半成品。重点是保留动作与既有操作、完成当前 AT 收尾、整理已安装地图及修复；未完成制作进入[下一轮清单](R44_STAGE_NEXT_ROUND.md)。**这不是全域重构完成版，也没有新增用户认可记录。**

Minecraft **1.20.1** / Forge **47.4.10** / Java **17**。当前源码网络协议 **49**，联机客户端和服务端必须使用同批 mod。完整与普通客户端的 mod 应为相同 SHA-256；视觉资源选择不改变功能和协议。若包内清单与本文不同，以实际封包回读记录为准，并把差异记录为验收问题。

## 1. 本轮交付状态及六包选择

本机交付目录：`artifacts/server-ready-r44-stage`。这是 **Encore 项目的 R44 验收批次**；为保持本批文件和安装步骤稳定，六包沿用 `Project_SEELE_R44_Stage_*` 文件名，PCL 实例名保持 **Project SEELE R44 Stage**。模组 ID `projectseele`、维度与存档标识不改。下列是本轮固定的六个包名。只有实际 ZIP、清单和回读结果齐全才算完成封包；本文件本身不证明文件已生成、安装成功或已上传。没有网络发布声明。

| 文件 | 使用方式 | 内容与边界 |
|---|---|---|
| `Project_SEELE_R44_Stage_Client.zip` | 想检查完整材质和光影时使用；拖入 PCL 导入独立实例 | mod、必需模型、配套存档及外部视觉资源；**光影默认关闭**，进入世界后自行开启对比 |
| `Project_SEELE_R44_Stage_Client_Plain.zip` | 想先检查基本操作、较低图形开销，或排查光影差异时使用 | 相同 mod／必需模型／配套存档；不含外部材质包、光影及 Oculus |
| `Project_SEELE_R44_Stage_Server.zip` | 部署 Java 17 专用服务器 | 服务端运行文件及配套世界；必须与本批客户端配对，不把 Oculus 等客户端图形组件装到服务器 |
| `Project_SEELE_R44_Stage_World.zip` | 服务器使用；也可作独立配套世界备份 | 配套阶段世界；存档目录为 `SEELE_R44_STAGE_WORLD`，目录下直接包含 `level.dat` |
| `Project_SEELE_R44_Stage_Textures.zip` | 完整客户端视觉资源备份 | 与完整 Client 视觉配置配套；普通客户端不必安装 |
| `Project_SEELE_R44_Stage_Shaders.zip` | 完整客户端光影资源备份 | 与完整 Client 配套；普通客户端没有 Oculus，不把此 ZIP 当作启用光影所需全部组件 |

完整 Client 与 Client_Plain **二选一即可开始**。为了对比，可导入两个独立实例，但不要让两个客户端同时写同一个本地存档。独立 Textures／Shaders 是备份，不必重复把它们叠加到完整 Client。Plain 的机体模型不是空白占位；必需模型在 mod 内嵌，不能用缺少外部资源包解释动作消失。

原 `SEELE43` 实例和原存档保留。本轮授权底本是本机 SEELE43；此前日志显示过远端连接，本机保存并不包含远端服务器后来产生的进度。配套阶段世界按原始本机进度加已核验静态施工差量组成，不能把施工／战斗 QA 的玩家、任务、机体、列车和运输进度当作玩家的新进度迁入。

## 2. 安装、首次开始与保存

### 2.1 本地客户端

1. 保留原实例，先备份原 `saves`、`config` 和自己改过的资源配置。Minecraft 完全退出后再复制存档。
2. 将选定 Client ZIP 拖入 PCL，导入独立 **Project SEELE R44 Stage** 实例。若同时保留完整与纯净版，把第二个实例命名为 **Project SEELE R44 Stage Plain**。不要手工覆盖 SEELE43 的 `mods` 或 `saves`。
3. 选择 Java 17，建议先分配 6–8 GB。启动器可能需要补齐 Minecraft／Forge 基础运行库；模组和配套资源是否齐全看本批实际清单。
4. 首次先保持光影关闭，进入 `SEELE_R44_STAGE_WORLD` 对应世界。确认角色、原机体、插入栓、NPC、任务和交通状态符合底本，再开始任务。
5. 使用 `/seele enter` 进入 SEELE 世界。指令需要本地作弊或服务器 OP 权限。若原世界里已有进行中的任务，先用状态指令记录再决定继续或取消。
6. 完整客户端第二轮再开启内置光影，记录所用光影名称、材质包顺序与视频设置。Plain 先以原生渲染验收；两个客户端差异要用同一区域、同一机体、同一动作比较。

### 2.2 专用服务器

1. 在新目录解压 Server ZIP，另行备份旧服务器目录；不要覆盖正在运行的服务器。
2. Server 包已内含本批世界，确认服务器目录下的 `SEELE_R44_STAGE_WORLD/level.dat` 存在；独立 World ZIP 可用于另外安装或备份，避免多套一层同名目录。
3. 确认 `server.properties` 的 `level-name=SEELE_R44_STAGE_WORLD`，阅读并接受 Minecraft EULA 后设置 `eula=true`。
4. 用 Java 17 启动包内服务端启动脚本。客户端全部使用本批协议 49；旧 R43 客户端不能混用。
5. 两个玩家分别用完整／Plain 客户端连接，先验收普通走路、物品与载具，再进行 EVA 战斗与任务。此处是人工验收步骤，不代表本轮已经完成双客户端全流程测试。

### 2.3 保存与回退

- 每次重要任务前，完整退出单机或正常停止服务端，再备份整个存档目录。保留 `level.dat`、玩家数据、维度、实体、模组 SavedData 和交通数据，不能只备份 `region`。
- 第一次检查先留一份未经试玩的阶段世界。正常游玩后不要再覆盖它来“修复”任务进度。
- 机库转移、飞机、列车或回收正在运行时，先等待安全停靠再正常退出；若测试的就是中断／重登，把中断时的状态与日志一并记录。
- 新错误需要回退时，先封存出错存档及 `logs/latest.log`／`crash-reports`，再恢复备份；不要反复使用强制恢复命令掩盖首个错误。
